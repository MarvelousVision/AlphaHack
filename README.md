# AlphaHack — AI AutoResearch

Автономная система проведения ML-экспериментов с использованием LLM-агента (Qwen) и Optuna. Проект разработан командой из трёх человек в рамках хакатона AlphaHack 2026.

## О проекте

Цель проекта — автоматизировать исследовательский цикл в машинном обучении: от подготовки табличных данных и выбора модели до оптимизации гиперпараметров и формирования итоговых предсказаний.

Система использует LLM в качестве агента, который анализирует информацию о задаче и историю экспериментов, формирует гипотезы и предлагает конфигурации для следующего запуска. Обучение моделей и оптимизация гиперпараметров выполняются отдельными ML-модулями.

## Возможности

- Поддержка регрессии и многоклассовой классификации.
- Автоматический выбор моделей и пространства поиска гиперпараметров с помощью Qwen.
- Оптимизация гиперпараметров с использованием Optuna.
- Валидация планов экспериментов через Pydantic.
- Хранение истории экспериментов и выбор лучшей конфигурации по результатам валидации.
- Управление временным бюджетом экспериментов.
- Автоматическая предобработка данных, генерация признаков и эксперименты с их исключением.
- Резервная baseline-модель на CatBoost и fallback-механизм при ошибках LLM API.
- Формирование и атомарное сохранение `submission.csv`.

## Архитектура

### Принцип работы

1. Подготовка данных и определение типа ML-задачи.
2. Обучение baseline-модели и сохранение первоначальных предсказаний.
3. Передача информации о задаче и истории экспериментов LLM-агенту.
4. Получение и валидация структурированного плана эксперимента.
5. Запуск оптимизации гиперпараметров с использованием Optuna.
6. Сохранение результатов эксперимента и передача обратной связи агенту.
7. При появлении нового лучшего результата — обучение модели с выбранными гиперпараметрами и обновление итоговых предсказаний.

## Основные компоненты

| Компонент | Назначение |
|---|---|
| LLM Agent | Анализ задачи и истории экспериментов, формирование гипотез, выбор модели и пространства поиска гиперпараметров; fallback при ошибках API |
| Orchestrator | Управление исследовательским циклом, контроль временного бюджета, проверка дубликатов и обновление предсказаний |
| Experiment Runner | Запуск ML-экспериментов, передача бюджета времени, обработка ошибок и формирование результатов |
| Experiment Tracker | Хранение истории, метрик, гиперпараметров и выбор лучшего эксперимента |
| Data Processing & ML | Предобработка данных, генерация и отбор признаков, обучение моделей, кросс-валидация и оптимизация через Optuna |

## Мой вклад в проект — ML Orchestration & Backend

В команде я отвечала за разработку управляющей части ML-системы и интеграцию LLM-агента с модулем машинного обучения. Моя основная задача заключалась в автоматизации полного цикла экспериментов — от получения гипотезы до сохранения предсказаний.

### Реализованные компоненты

| Модуль | Мой вклад |
|---|---|
| `core/orchestrator.py` | Управление итеративным циклом исследований, передача истории агенту, проверка дубликатов, распределение времени между экспериментами и финальным обучением |
| `core/experiment_runner.py` | Выполнение планов экспериментов, передача временного бюджета в Optuna, обработка исключений и унификация результатов |
| `core/experiment_tracker.py` | Хранение истории экспериментов, метрик, пространств поиска и лучших гиперпараметров; выбор лучшего эксперимента с учётом направления оптимизации метрики |
| `core/schemas.py` | Pydantic-схемы для структурированных планов и результатов экспериментов, валидация параметров |
| `solution.py` | Интеграция компонентов в единый ML-пайплайн, обучение CatBoost baseline, передача конфигураций в ML-модуль и сохранение итоговых предсказаний |

### Инженерные решения

- Реализовала обратную связь между LLM-агентом и ML-модулем: результаты предыдущих экспериментов используются при формировании новых гипотез.
- Подключила оптимизацию гиперпараметров через Optuna и эксперименты с исключением признаков на основании структурированного плана агента.
- Реализовала контроль оставшегося времени в исследовательском цикле и резервирование времени для финального обучения.
- Обеспечила сохранение baseline-предсказаний до запуска LLM-агента, чтобы при ошибках исследовательского цикла оставался резервный результат.
- Реализовала атомарное обновление `submission.csv`, уменьшающее риск повреждения файла при прерывании записи.
- Провела интеграционное тестирование Backend, проверку цепочки «агент → Optuna → предсказания» на синтетических данных и проверку финальной ZIP-сборки.

## Установка и сборка

```bash
git clone https://github.com/YaroslavArdintsev/AlphaHack.git
cd AlphaHack
python -m venv .venv
```

Активация виртуального окружения в PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Установка зависимостей и сборка:

```bash
pip install -r requirements.txt
python build_zip.py
```

Сборщик формирует `solution_boosters.zip` для запуска на платформе соревнования. Для работы LLM-агента необходимо настроить доступ к API Qwen. Секретные ключи не должны храниться в репозитории.

## Тестирование

В процессе разработки проверены:

- формирование baseline-предсказаний для обеих ML-задач;
- fallback агента при имитации ошибки API;
- интеграция оркестратора, runner и tracker с тестовым исполнителем;
- цепочка генерации плана, оптимизации Optuna и получения предсказаний на небольшом синтетическом датасете;
- целостность ZIP-архива и импорты в собранной версии.

Решение успешно завершило запуск на платформе соревнования. Полная проверка качества моделей и соблюдения временного бюджета для всех сценариев не проводилась.
